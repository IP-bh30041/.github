<h2>稳定性有三个层次，别只看一个</h2>
<p>说一条住宅 IP 稳定，可能指三件不同的事：连接不断（不掉线）、速度不飘（延迟波动小）、身份不变（地址不漂移）。三者可以独立发生，也可以同时出问题。只盯着其中一个，很容易在另外两个上栽跟头。</p>
<p>比如「从不掉线但每三天换一次地址」的资源，从连接角度看很稳，从运营角度看完全不可用。判断稳定性必须三个层次一起看。</p>

<h2>为什么住宅资源天然不如机房稳</h2>
<p>因为它的物理条件不同。家庭宽带的供电、散热、线路质量都不如机房；同一线路上的其他用户会占用带宽；运营商的调度策略也会带来波动。这些不是服务商能完全消除的，只能通过筛选与运维降低。</p>
<p>理解这一点，就不会用「机房级稳定」的标准去要求住宅资源，也就不会因为偶发波动就判定资源不可用。合理的标准是「掉线频率低、恢复快、地址不变」。</p>

<h2>购买时要问的五个问题</h2>
<p>一，这个地址近期是否发生过变更，变更原因是什么。二，是否有可用性记录或监控数据。三，断线后的恢复机制是什么，是否需要人工干预。四，是否有备用地址，切换需要多久。五，可用性承诺到什么程度。</p>
<p>五个问题里，第四个最实际。任何资源都可能出问题，关键是出问题时多久能恢复。答得出具体时限的，说明流程成熟。</p>

<h3>关于可用性承诺</h3>
<p>合理的承诺是区间加响应时限，例如「可用率不低于某个水平，故障响应在若干小时内」。要求「永不掉线」的承诺，反而是不专业的信号。</p>
<h3>关于监控数据</h3>
<p>愿意提供监控数据的服务商，通常对自己的资源有信心。拿不到数据的，只能自己测，而自测需要时间。</p>

<h2>自己怎么测</h2>
<p>四项。一，连续监测：用工具定期探测，记录延迟、丢包、断线次数。二，地址核对：定期查询出口地址，看是否变化。三，时段对比：分别在高峰与非高峰测，看衰减幅度。四，行为观察：记录登录时是否频繁触发额外验证。</p>
<p>四项至少持续两周。单日测试看不出规律，很多问题在第二周才显现。</p>

<h2>不稳定的常见原因</h2>
<p>原因一，共享程度高。同一线路上的其他用户占满带宽。原因二，家庭环境问题。散热、供电、线路老化。原因三，运营商调度。晚间高峰限速或路由调整。原因四，配置问题。MTU 不匹配、DNS 设置不当。</p>
<p>前三个是资源侧问题，第四个是自己的问题。排查时先排除第四个，再去和服务商沟通，效率更高。</p>

<h2>把「恢复时间」当成核心指标</h2>
<p>任何资源都会出问题，差别在于多久能恢复。所以比「是否稳定」更有意义的问题是：断了之后，多久能重新可用？是自动恢复还是要人工干预？干预需要多久？三个答案加起来，才是真实的可用性。答得越具体，说明流程越成熟；答「不会断」的，反而要警惕。</p>
<h2>常见问答</h2>
<h3>掉线几次算不正常</h3>
<p>没有统一标准。参考判断是：每天都有规律性断线，说明有问题；偶发一两次且能自动恢复，属正常范围。</p>
<h3>地址变了一定要换吗</h3>
<p>不一定。偶发一次可以接受，频繁变更说明资源侧有问题，应考虑更换。</p>
<h3>能要求固定地址吗</h3>
<p>可以，签约时明确保号条款。多数方案支持，但可能需长期合约。</p>
<h3>怎么判断是共享导致的</h3>
<p>看是否只在高峰时段变慢，且延迟波动大。共享资源的特征就是「忙时差、闲时好」。</p>
